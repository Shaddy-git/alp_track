## 2. Назначение и цели создания системы

### 2.1. Назначение продукта
Система предназначена для централизованного хранения, обработки и анализа информации о горах, альпинистах, группах и совершённых восхождениях, а также для автоматизации процесса формирования групп с учётом квалификации участников.

### 2.2. Цели создания продукта
- Автоматизация учёта участников клуба и их квалификации.
- Снижение рисков при формировании групп благодаря автоматической проверке уровня подготовки.
- Ведение статистики и формирование отчётов по восхождениям.
- Обеспечение безопасного хранения персональных данных и разграничения прав доступа (RBAC).

## 3. Характеристика объекта автоматизации

### 3.1. Описание объекта автоматизации
Деятельность альпинистского клуба, включающая ведение реестра гор, регистрацию альпинистов, формирование групп и фиксацию фактов восхождений. Характеризуется наличием связей «многие-ко-многим» (альпинисты и группы) и необходимостью работы с временными метками (даты восхождений).

### 3.2. Участники процесса
- **Администратор:** управляет справочником гор, регистрирует пользователей, назначает роли.
- **Инструктор (руководитель группы):** создаёт группы, добавляет участников, фиксирует восхождения.
- **Альпинист:** просматривает свои восхождения, доступные горы, ищет группы для участия.

## 4. Требования к продукту

### 4.1. Требования к продукту в целом
- **Структура:** клиент-серверная архитектура. Backend реализует HTTP API (REST), Frontend -- веб-интерфейс.
- **Функционирование:** приложение должно работать в браузере, обеспечивать отклик на запросы пользователя в течение 2 секунд.
- **Надёжность:** обработка некорректных запросов (возврат HTTP-статусов 400, 401, 403, 404, 500) без раскрытия внутренней структуры приложения (стек-трейсов).
- **Безопасность:**
  - Хранение паролей только в виде хешей (bcrypt/argon2/scrypt).
  - Защита от основных уязвимостей OWASP Top 10 (SQL-инъекции, XSS, Broken Access Control).
  - Использование JWT-токенов.

### 4.2. Требования к видам обеспечения
- **Информационное обеспечение:** реляционная база данных (PostgreSQL). Схема БД включает сущности: `users`, `mountains`, `groups`, `group_members` (M:N), `ascents`.
- **Программное обеспечение:** язык программирования Python, система контроля версий Git.
- **Лингвистическое обеспечение:** интерфейс и документация на русском языке.
- **Техническое обеспечение:** ПК разработчика, сервер для развёртывания (или локальная среда).

### 4.3. Требования к ПО (функциональные)
- **Регистрация и авторизация:** создание учётной записи, вход в систему, разграничение прав доступа (RBAC).
- **Управление справочником гор:** CRUD записей о горах (название, высота, страна, категория сложности).
- **Управление альпинистами:** CRUD записей об альпинистах (ФИО, уровень подготовки).
- **Управление группами:** создание групп, добавление/удаление участников (реализация связи многие-ко-многим).
- **Учёт восхождений:** фиксация факта восхождения (альпинист, гора, группа, дата, статус).
- **Формирование отчётов:** вывод статистики («Список альпинистов, покоривших Эльбрус», «Количество успешных восхождений за год»).

### 4.4. Специфические требования (бизнес-правила)
1. **Правило безопасности:** альпинист не может быть добавлен в группу для восхождения на гору, если его уровень подготовки (`experience_level`) ниже категории сложности горы (`difficulty_level`).
2. **Валидация дат:** дата восхождения не может быть раньше даты начала группы или позже даты её окончания.
