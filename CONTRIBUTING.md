# 📜 Правила внесения изменений

Обязателен к прочтению каждому участнику команды.

## 🔀 Ветвление

- **`main`** — стабильная ветка. Коммит только через Pull Request.
- **`feature/название`** — для новых функций.
- **`fix/название`** — для исправлений.
- **`docs/название`** — для документации.

## ✅ Обязательные команды проверки перед коммитом

```bash
# 1. Проверка стиля кода
flake8 backend/

# 2. Проверка синтаксиса
python -m compileall backend/

# 3. Проверка, что .env не попадёт в коммит
git diff --cached --name-only | grep -E '\.env$' && echo "❌ ОШИБКА: .env в коммите!" && exit 1

# 4. Просмотр всех изменений
git diff --cached
```

## 🚫 Запрещённые действия

- ❌ Прямой коммит в `main` (только через PR)
- ❌ Коммит файлов `.env`, `*.db`, `.venv/`, `__pycache__/`
- ❌ Коммит паролей, токенов, ключей в открытом виде
- ❌ `git push --force` в общие ветки
- ❌ Удаление тестов ради прохождения проверки
- ❌ Мержить свой PR без ревью другого участника

## 📝 Формат коммитов (Conventional Commits)

```
<тип>: <краткое описание>
```

| Тип | Когда |
|-----|-------|
| `feat:` | Новая функциональность |
| `fix:` | Исправление бага |
| `docs:` | Документация |
| `refactor:` | Рефакторинг без изменения логики |
| `test:` | Тесты |
| `chore:` | Служебные изменения |
| `style:` | Форматирование |

**Примеры:**
- `feat: добавлена регистрация пользователей`
- `fix: исправлена валидация email`
- `docs: обновлён README`

## 🚦 Процесс работы

### 1. Получить актуальное состояние

```bash
git checkout main
git pull origin main
```

### 2. Создать ветку

```bash
git checkout -b feature/краткое-название
```

### 3. Работать и коммитить

Один коммит = одна логическая единица.

### 4. Отправить ветку

```bash
git push origin feature/краткое-название
```

### 5. Создать Pull Request на GitHub

Заполнить описание: что сделано, как проверить, ограничения.

### 6. Code Review

Минимум 1 одобрение от другого участника.

**Критические файлы** — требуют отдельного внимания:
- `backend/services/ascent_service.py`
- `backend/config.py`
- `.gitignore`
- `CONTRIBUTING.md`

### 7. Слияние

После одобрения — merge через GitHub, затем удалить ветку.

## 🛡️ Правила безопасности

1. Никогда не коммить `.env`
2. Никогда не хардкодить пароли
3. Всегда валидировать входные данные
4. Всегда использовать параметризованные запросы (ORM)
