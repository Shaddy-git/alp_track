# Требования безопасности и правила развёртывания

## Приложение
- Не запускается от root. systemd-служба работает под пользователем `appuser`.
- Приложение не имеет sudo-прав.
- Код приложения (`/opt/myapp`) не writable для `appuser` — приложение не может менять само себя.

## SSH
- Root login по SSH запрещён (`PermitRootLogin no`).
- Доступ только по SSH-ключам, без паролей.
- Отдельные пользователи: администратор и пользователь запуска приложения.

## Сеть
- APP-сервер: открыт только порт приложения (8000) и SSH.
- DB-сервер: порт 5432 открыт только для APP-сервера.
- PostgreSQL `pg_hba.conf` разрешает подключение только с APP-IP и только роль `appuser` к базе `appdb`.

## Секреты
- Секреты хранятся в `/etc/myapp/app.env` с правами `640 root:appuser`.
- Пароли, JWT-ключи, `SECRET_KEY` не хранятся в репозитории.
- В репозитории только шаблон `.env.example` без реальных значений.
- `.env` в `.gitignore`.

## Внесение изменений (GitFlow)
- Постоянные ветки: `main` (только релизы) и `develop` (интеграция).
- Любая задача — через `feature/*` от `develop`.
- Слияние — только через Pull Request с ревью.
- Релиз — через `release/*` из `develop` в `main` и тег.
- Срочные правки — через `hotfix/*` из `main`, затем merge и в `main`, и в `develop`.

## Проверки перед merge
- Приложение запускается и отвечает на `/health`.
- Миграции применяются без ошибок.
- Секреты не попали в diff (`git diff` без паролей).
